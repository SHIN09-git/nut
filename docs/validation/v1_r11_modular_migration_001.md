## 2. 模拟更新顺序

R11 保留既有固定 Tick 语义：

```text
拒绝非连续 Tick
→ 应用有序高层命令
→ 推进逐室环境效果
→ 更新迁巢候选与稳定窗口
→ 推进生命周期
→ 校验现有任务
→ 推进现有任务
→ 优先分配废物／侦察／迁巢任务
→ 分配育幼搬运／喂食／觅食
→ 收集第五章证据并刷新章节状态
→ 校验所有权、区域图、任务、资源和章节不变量
→ 创建新快照
```

双室放置命令只携带设施类型、逻辑槽位和方向。下一 Tick 从冻结目录分配育幼室／功能室稳定 ID，建立内部连接，再按端口映射重建外部连接。UI 不提交区域 ID、环境初值或连接。

## 3. 搬运与所有权

迁巢继续使用 R9 的显式任务：

```text
IDLE
→ MOVING_TO_MEMBER
→ PICKING_UP
→ CARRYING_TO_ZONE
→ DROPPING
→ IDLE
```

- 目标巢必须已发现、舒适、可达、持续稳定且明显优于蚁后当前区域。
- 幼体按稳定实体 ID 选择；全部幼体抵达后才允许选择蚁后。
- 未被搬运的幼体和蚁后恰好属于一个区域；被搬运时区域 ID 为空且恰好属于一个工蚁任务。
- 目标失效时，已拾取成员返回来源区域；任务、预订与携带关系被清理。
- 双室巢一旦被实体、任务或叠放设施引用，旋转会被模拟命令边界拒绝，避免房间宿主映射改变。
