## 结论

R3 已把 R2 的版本化存档核心接入真实玩家路径。默认入口现在是应用标题页；玩家可以创建一个主档案、继续、在暂停菜单保存、保存后返回标题、查看档案摘要、显式恢复上一份备份，并在二次确认后覆盖或删除档案。

设置保存在独立的 `user://settings.json`，不进入权威游戏档案。当前提供主音量、1280×720／1920×1080、窗口／全屏、简体中文／临时英文、100%／125%／150% UI 缩放和减少动效。游戏内暂停菜单与标题设置页共享同一设置状态；人工检查发现并修复了两者缩放显示不同步的问题，回归测试已锁定该边界。

## 实际玩家路径

```text
标题页
→ 新游戏
→ Tick 0 准备门
→ 开始观察
→ 暂停并保存
→ 保存并返回标题
→ 档案页查看摘要／备份状态
→ 继续
→ 恢复相同 Tick、暂停状态、权威模拟和冻结配置
```

主档损坏时，“继续”会选择可验证的备份候选；档案页仍提供显式恢复上一份备份。恢复和删除都经过确认面板。

## 自动覆盖

- 标题、新游戏、暂停保存、返回标题、继续和暂停状态恢复。
- 主档摘要、轮换备份、损坏主档回退、显式备份恢复和确认删除。
- 设置文件与档案文件相互独立；坏设置安全回退默认值。
- 主音量、分辨率、全屏、语言、三档 UI 缩放和减少动效持久化。
- 游戏内设置与标题壳层即时同步；返回标题后控件选中项和视觉缩放一致。
- 1280×720 与 1920×1080 的标题、档案、设置和暂停页面布局边界。
- 键盘焦点与 `Esc` 返回。
- 减少动效关闭蚁后待机摆动、阶段脉冲和位置帧间插值，但不改变模拟快照。
- 旧生命周期、湿度、糖水、组合模拟、存档迁移和 10,000 Tick soak 继续通过。

## 人工窗口验证

实际启动 Godot 窗口并检查：

- 1280×720、100%：标题、设置、准备门、游戏、暂停菜单和档案页无重叠或越界。
- 1280×720、150%：标题、准备门、游戏和双栏暂停菜单无重叠或越界；标题副文案保持一行。
- 1920×1080、100% 与 150%：游戏和暂停菜单保持可读，档案页和标题页完整显示。
- 暂停菜单“保存游戏”显示成功反馈；“保存并返回标题”先保存再回到档案／标题路径。
- 档案页显示阶段、观察时间、最近观察、保存时间和备份恢复入口。
- “继续”恢复相同 Tick 的暂停会话，并重新显示暂停菜单。
- 游戏内把 UI 缩放改为 150% 后返回标题，标题层立即使用 150%；标题设置页也显示 150%。随后已把本机设置恢复为 1280×720、100%、简体中文、减少动效关闭。
- 关闭 F3 时仍能辨认工蚁携带幼体；R3 没有把内部 ID 或诊断值加入普通界面。

本轮没有人工执行档案删除，避免删除本机验证档案；确认删除及实际删除由自动场景测试覆盖。全屏和临时英文的实际窗口检查沿用 M5 记录，本轮没有重复执行，不能据此新增人工通过声明。

人工流程在 `user://` 创建了本机档案与设置；仓库中没有加入这些文件。

## 最终 diff 自审

- 默认入口改为应用壳层；保留连续观察、湿度、糖水和生命周期调试场景。
- `MainController` 仍只协调时钟、模拟、命令、快照和界面；档案壳层不取得私有模拟模型。
- 存档只发生在合法 Tick 边界，继续使用 R2 的 checksum、严格重建、原子提交和备份语义。
- 设置与权威档案分离；缩放和减少动效只改变展示，不改变模拟。
- 没有改变固定 Tick、物种／湿度／觅食 `.tres`、生命周期边界或现有状态机。
- 没有加入自动存档、章节、设施、营养、经济、Steam、正式素材、音频或第三方插件。
- Godot 可执行文件、`.godot/`、日志、构建产物和本机 `user://` 数据未进入版本控制。
- `DEVELOPMENT_PLAYBOOK.md` 保持未读取、未修改、未暂存。
