# v1 性能与规模预算

状态：R1 技术规格；R12 完整档案长时证据与 R16 最大规模候选证据已记录

这些是后续验证目标，不是当前 M5 已达到的声明。达到证据前不扩大规模。

## 支持目标

- Windows x86_64。
- 1280×720 与 1920×1080，窗口和全屏。
- Godot 4.7.1 Compatibility 渲染器。
- 目标 60 FPS；低规格模式允许锁定 30 FPS，但固定 Tick 语义不变。
- 0.1 秒固定模拟 Tick。

## 首发规模

| 对象 | 正常目标 | 压力上限 |
| --- | ---: | ---: |
| 蚁后 | 1 | 1 |
| 工蚁 | 60 | 80 |
| 幼体总数 | 120 | 180 |
| 同时可见蚂蚁／幼体节点 | 160 | 240 |
| 设施实例 | 30 | 48 |
| 逻辑区域 | 24 | 36 |
| 连接实例／闸门 | 48 | 72 |
| 食物源 | 12 | 20 |
| 废物权威 | 区域污染与托盘容量聚合值 | 不创建独立废物实体 |
| 活跃工蚁任务 | 60 | 80 |
| 内存中的观察事件 | 全局保留 64 | 全局保留 64 |

超过压力上限需要新的性能证据和用户批准；不承诺数百只工蚁。

## 帧与 Tick 预算

| 项目 | 60 FPS 目标 | 压力门槛 |
| --- | ---: | ---: |
| 单渲染帧总 CPU | ≤ 16.67 ms | P95 ≤ 22 ms |
| 单固定 Tick 模拟 | P95 ≤ 2 ms | 最大 ≤ 5 ms |
| 快照创建 | P95 ≤ 1.5 ms | 最大 ≤ 4 ms |
| View 快照应用 | P95 ≤ 3 ms | 最大 ≤ 7 ms |
| 布局图重建 | P95 ≤ 5 ms，仅布局变化时 | 最大 ≤ 15 ms |
| 自动保存序列化 | 后台准备 ≤ 50 ms；主线程提交 ≤ 4 ms | 不得推进 Tick或丢帧超过 100 ms |

现有 `SimulationClock` 的单帧 Tick 处理上限继续保留。积压不丢弃、不改变 Tick 语义；若长时间无法排空，显示性能警告并暂停安全状态，而不是跳过模拟。

## 内存与存档

- 运行时工作集目标：≤ 700 MB；压力上限：≤ 1.2 GB。
- 单档主存档目标：≤ 10 MB；硬上限：32 MB。
- 当前保存一个主档案和至少一个恢复候选，总档案磁盘目标：≤ 64 MB。
- 快照不能持有 Node、纹理或历史完整副本。
- 事件和个体历史使用有界容量；长期统计使用聚合值，不无限追加。

## 算法约束

- 工蚁决策只在空闲、目标失效或间隔到期时运行。
- 稳定 ID 排序结果在集合不变时缓存；不在每 Tick 重复排序所有实体。
- 可达图只在设施、连接、方向、可用状态或闸门变化时重建。
- 不为小规模路径引入通用导航框架；使用稳定区域图和有界路径。
- View 节点按稳定 ID 复用。只有性能证据表明节点创建成为问题时才评估对象池。
- 快照只发布当前 View／UI 需要的只读字段；不把派生缓存或完整存档结构复制到每帧。

## 基准场景

1. **章节 1 最小场景**：1 蚁后、20 幼体、试管。
2. **章节 3 正常场景**：20 工蚁、60 幼体、10 设施、12 区域。
3. **章节 5 正常场景**：60 工蚁、120 幼体、30 设施、24 区域。
4. **最大规模 soak**：80 工蚁、180 幼体、48 设施、36 区域、
   72 连接、20 食物源和 80 个活跃任务；废物继续使用已实现的区域污染
   与托盘容量聚合值。
5. **布局突变**：连续合法放置／旋转／开关闸门，验证缓存失效和路径重建。
6. **存读压力**：活跃任务、待处理命令、暂停和章切换边界反复保存／加载。

## 验证

- 每个代码里程碑运行受影响的微基准和标准回归。
- R12 运行 144,000 Tick 脚本化完整流程。
- R16 运行 300,000 Tick 最大规模 soak。
- 记录平均、P95、最大帧时／Tick 时间、工作集、存档大小和实体数量。
- 相同命令序列在 1×、4×、16×、连续运行和存读后快照签名一致。
- 不允许 NaN、无穷、负资源、重复任务、非法所有权或无法排空的命令队列。

### R12 当前档案实测

2026-07-29 使用 Windows、Godot `4.7.1.stable` Compatibility 渲染器对应代码，在当前正式六章的小型档案上运行 `tests/performance/act1_144k_soak.gd`：

| 指标 | 结果 |
| --- | ---: |
| 连续固定 Tick | 144,000 |
| 起止 Tick | 46 → 144,046 |
| 总用时 | 52.731 秒 |
| 平均单 Tick | 0.312 ms |
| P95 单 Tick | 0.561 ms |
| 最大单 Tick | 3.461 ms |
| Godot 静态内存 | 34,119,576 bytes |
| 中点规范化存档 | 30,431 bytes |

脚本在中点执行实际 Envelope 存读和快照签名比较，每 1,000 Tick 检查有限环境值、非负资源、报告完成状态与栖息地单一所有权，并周期提交已实现的糖液／蛋白／清理动作。结果没有 NaN、无穷、负资源、非法所有权、崩溃或签名漂移。

这组结果证明当前六章小型档案达到 Tick 预算；最大规模由下面的 R16
证据单独覆盖。

### R16 最大规模实测

2026-07-29 使用 Windows 11 64-bit（10.0.26100）、AMD Ryzen 7 7800X3D、
32 GB RAM、NVIDIA GeForce RTX 4070 SUPER、Godot `4.7.1.stable`
Compatibility 渲染器运行
`tests/performance/act1_300k_max_scale_soak.gd`。

最大规模夹具精确包含 80 工蚁、180 幼体、48 设施、36 区域、72 连接、
20 食物源和 80 个活跃搬运任务。权威快照保留全部 260 个体；View 依稳定
ID 保留全部活动工蚁和当前搬运幼体，并把同时存在的 `AntView` 限制为
240。超过 160 个可见实体时只降低程序化轮廓细节，不隐藏行为或改变模拟。

| 指标 | 结果 |
| --- | ---: |
| 连续固定 Tick | 300,000 |
| 起止 Tick | 46 → 300,046 |
| 总用时 | 401.966 秒 |
| 平均单 Tick | 1.330 ms |
| P95／P99 单 Tick | 2.030／2.375 ms |
| 最大单 Tick | 21.384 ms |
| 超过 5 ms | 42 / 300,000（0.014%） |
| 平均／P95 快照 | 2.646／3.670 ms |
| 最大快照 | 4.158 ms |
| 超过 4 ms 快照 | 2 / 300 |
| 平均／P95 View 应用 | 2.633／3.680 ms |
| 最大 View 应用 | 5.041 ms |
| 超过 7 ms View 应用 | 0 / 300 |
| 起始／峰值／最终静态内存 | 37,395,744／42,751,944／46,550,388 bytes |
| 每 1,000 Tick 内存样本趋势 | +161.72 bytes／sample |
| 规范化存档 | 210,488 bytes |
| 最终签名 | `ad21e7f54e3a2832223048f4a8f4748fa108e60b5a5dbf02a8e11e493564dd3e` |

每 1,000 Tick 执行完整所有权、有限环境值、实体数量、活动任务和完成档案
检查。结果没有崩溃、NaN、无穷、负资源、无主幼体、重复实体或任务泄漏。
P95 Tick 比 2 ms 目标高 0.030 ms；极低频 Tick 调度离群和两次快照离群
超过压力表的绝对最大值，但没有接近 `SimulationClock` 的 100 ms 单步安全
上限，也没有丢 Tick。它们作为 R16 已知非阻断压力限制保留，不报告为预算
全绿。

同一最大场景在非 headless 1280×720 窗口中采样 600 个真实渲染帧：

| 指标 | 结果 |
| --- | ---: |
| 平均帧 | 4.703 ms |
| P95／P99 帧 | 5.529／6.825 ms |
| 最大帧 | 7.269 ms |
| 超过 22 ms | 0 / 600 |

该帧样本来自开发机，不代替低规格外部硬件测试；它证明当前候选在记录机器
上满足最大规模渲染压力线。

## 停止条件

- 为达到规模需要改变固定 Tick 语义或丢 Tick。
- 需要在普通 UI 隐藏行为才能维持性能。
- 60 工蚁正常场景无法在目标机器稳定运行。
- 存档或快照通过共享可写对象换取性能。
- 性能优化要求引入尚无证据需要的 ECS、行为树或第三方插件。
