# R20 无说明行为辨认协议

本协议只验证 `CODEX_POST_R17_GAME_EXPERIENCE_OPTIMIZATION_PLAN.md` 的 R20
画面辨认 Gate，不验证教程理解、章节节奏、好玩程度或完整发布质量。

状态：候选准备中。只有冻结候选、哈希和本协议完全匹配时才能收集正式样本。

## 1. Gate 与样本冻结

R20 Gate 的原文要求是：

> 5 名未看说明的测试者中至少 4 人能从画面识别“走路、搬幼体、带食物、
> 喂幼体、清理、迁巢”中的至少 4 种。

正式轮次必须在测试前登记参与者顺序。主要分析只使用预登记顺序中的前 5
名有效参与者；无效样本保留记录并按顺序追加替补，不得在看过结果后挑选
表现较好的 5 人。

没有 5 名有效参与者及逐项原话时，结论只能是 `INCOMPLETE`。达到阈值才可
写为 `PASS`；未达到则写为 `FAIL`。自动测试、本机窗口检查、开发者判断和
空白模板都不能替代真人样本。

## 2. 冻结候选

本轮只允许使用 `docs/validation/r20_behavior_recognition_candidate_001.md`
中记录的同一份 Windows ZIP、EXE 与 PCK。开始每名参与者前都要校验三项
SHA-256。任一哈希不同，停止该轮并建立新候选，不得混池。

参与者只接触解压后的游戏文件，不接触：

- 本协议、评分规则或结果模板；
- `README.md`、`GDD.md`、计划文件或开发记录；
- F3 调试层、实体 ID、任务枚举或目标 ID；
- 他人的录屏、答案或讨论；
- 带有“正确动作名称”的截图、图例或说明。

## 3. 有效参与者

参与者必须同时满足：

- 未参与本项目开发、测试或素材制作；
- 测试前未看过本项目的玩法说明、开发直播、截图说明或行为名称；
- 第一次接触本冻结候选；
- 使用全新档案和干净解压目录；
- 全程没有场外玩法提示；
- 六种目标行为均在其画面中清楚出现，并保留可审计录屏与逐项原话；
- ZIP、EXE、PCK 哈希均与冻结候选匹配。

以下情况标记无效，并按预登记顺序招募替补：

- 参与者已知道目标行为或评分门槛；
- 记录员解释了动作、目标、章节答案或正确操作；
- F3 或其他诊断文字出现在用于辨认的画面中；
- 使用错误构建、旧存档或被修改的配置；
- 任一目标行为没有实际出现在画面中；
- 缺少对应原话，或由记录员事后代写参与者答案；
- 参与者复制了界面文字而不是描述看到的动作。

无效样本仍保留匿名编号、无效原因和候选哈希，不删除、不替换原记录。

## 4. 隐私与记录

- 只在仓库中使用 `P01`、`P02` 等匿名编号。
- 不提交姓名、联系方式、声音、面部、桌面通知或原始录屏。
- 录屏前取得同意；原始文件放在仓库外的受控位置。
- 仓库只提交经脱敏的逐项原话、时间码、评分依据与哈希。
- 不记录与判断无关的个人资料。

## 5. 测试前准备

1. 预登记 `P01`～`P05`；替补从 `P06` 起顺延。
2. 校验候选 ZIP，解压到新的空目录，再校验 EXE 与 PCK。
3. 为参与者准备新的本机档案目录，不加载开发者或其他参与者的存档。
4. 记录 Windows 版本、显示分辨率、UI 缩放、语言和减少动效设置。
5. 记录员准备屏幕录制并确认 F3 关闭。
6. 记录员单独持有本协议；参与者只收到下一节文字。

## 6. 给参与者的唯一开场文字

记录员只能逐字提供本节，不展示后续问题和评分规则：

> 这是一个仍在开发中的蚂蚁观察游戏。请从新档案开始，只根据游戏画面和
> 游戏内可见信息进行观察与操作。请在你认为体验完成时告诉我。过程中我
> 不会解释蚂蚁动作或给出正确玩法；如果你不确定，可以直接说出你正在想
> 什么。

不得补充目标行为列表、预期章节、推荐速度、正确工具、迁移方向或结局条件。

## 7. 收集流程

### 7.1 自然观察

1. 从全新档案开始录屏。
2. 参与者自行操作；记录员只处理启动故障或安全问题。
3. 记录六种目标行为首次清晰出现的时间码，但不向参与者读出行为名称。
4. 参与者到达稳定群落总结，或明确表示结束后，停止主动操作。
5. 若任一目标行为没有清晰出现，本样本不能进入 R20 主要分析。

### 7.2 无标签回看

在任何解释或复盘前，从该参与者自己的录屏中截取六段 5～15 秒的连续画面。
每段只能包含一种主要目标行为，保留世界上下文，但不显示 F3、字幕标注、
任务枚举或记录员提示。

六段的播放顺序由测试前生成并记录的顺序决定。对每段只问：

> 这段画面里，工蚁正在做什么？请用自己的话描述；如果看不出来，可以说
> 看不出来。

可以追加一次中性追问：

> 画面中什么线索让你这样判断？

不得念出六个目标行为，不得给选择题，不得纠正答案。逐字记录回答和
1～5 的自报信心；信心不参与 Gate 计分。

## 8. 六种行为的事后编码规则

编码只根据参与者原话与对应片段，不能根据“参与者大概懂了”推断。

| 稳定 ID | 目标行为 | 记为识别的最低语义 | 不足以识别的回答 |
| --- | --- | --- | --- |
| `WALK` | 走路 | 工蚁沿巢室、通道或觅食区从一处移动到另一处 | “在动”“动画在播” |
| `CARRY_BROOD` | 搬幼体 | 工蚁拾取、携带或放下卵／幼虫／蛹等幼体 | 只说“搬东西”，无法指出幼体或育幼对象 |
| `CARRY_FOOD` | 带食物 | 工蚁携带、运回糖液或食物 | 只说“嘴边有颜色” |
| `FEED_BROOD` | 喂幼体 | 工蚁把食物交给幼体、给幼体喂食或照料进食 | 只说“靠近幼体” |
| `CLEAN` | 清理 | 工蚁拾取、搬走或处理废物／垃圾 | 只说“在走”或“搬东西”，无法指出废物 |
| `MIGRATE` | 迁巢 | 工蚁通过连接把幼体或群落成员搬到另一巢室，表达群落换巢 | 只识别一次普通室内搬运，未表达跨巢室转移 |

允许自然同义词和不专业名称，例如“白色小宝宝”可指幼体，“垃圾颗粒”可指
废物。拼写、术语准确性和信心不影响计分。

每项编码必须包含：

- 原始时间码；
- 参与者逐字回答；
- `recognized = 0/1`；
- 一句引用原话的编码依据。

有争议时按 `0` 计，并在汇总中标记需要第二名评审者复核。评审者不能看到
其他参与者的得分后再改变规则。

## 9. Gate 计算

1. 对每名有效参与者汇总六项 `recognized`。
2. `recognized_count >= 4` 记为该参与者达到 R20 行为辨认阈值。
3. 前 5 名有效参与者中至少 4 人达到阈值，R20 行为辨认 Gate 才为 `PASS`。
4. 前 5 名有效参与者中少于 4 人达到阈值，Gate 为 `FAIL`。
5. 有效参与者不足 5 人，Gate 为 `INCOMPLETE`。

同时报告每种行为的识别人数，但不得用“总识别项很多”替代 4/5 的逐人门槛。

## 10. 交付物

正式轮次完成后应有：

- 一份复制自 `r20_behavior_recognition_results_template.csv.example` 并改名为
  `.csv` 的脱敏逐项记录；
- 一份复制自 `r20_behavior_recognition_summary_template.md` 的汇总；
- 候选 ZIP／EXE／PCK 哈希；
- 预登记顺序与无效样本原因；
- 仓库外原始录屏位置及访问责任人；
- Gate 的 `PASS`、`FAIL` 或 `INCOMPLETE` 结论。

不得提交原始个人数据或用合成行、自动生成回答、开发者自测替代参与者。
