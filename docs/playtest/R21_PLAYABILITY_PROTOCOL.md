# R21 第 1～2 章无讲解可玩性协议

## 目的与边界

本协议只验证 R21 第 1～2 章是否形成可理解的：

> 观察问题 → 预测 → 环境干预 → 行为反馈 → 推论

至少招募 5 名此前没有玩过本项目、没有读过设计文档或开发说明的参与者。
测试者只接触冻结候选包；主持人不解释界面、目标行为、糖液位置取舍或正确
推论。R20 Gate 的用户豁免不改变本协议，也不计作 R21 结果。

## 预登记

分发候选前记录：

- 候选 ZIP 文件名与 SHA-256。
- 源码提交。
- 参与者招募顺序。
- 参与者是否首次接触。
- 录屏、操作日志和逐字回答的保存位置。

主要分析使用招募顺序中的前 5 名有效参与者。无效样本必须保留无效原因，并
按原招募顺序补充新参与者，不能按成绩挑选。

## 有效样本

参与者必须：

- 年满当地独立同意年龄，并明确同意记录测试；
- 能独立操作 Windows 鼠标和键盘；
- 未看过 R21 目标、正确推论、开发录像或答案；
- 从候选包的新档案开始；
- 完成或明确放弃第 1～2 章。

崩溃、录制完全失效、主持人误泄露答案或参与者并非首次接触时标记无效。
游戏内自行打开帮助不使样本失效，但应记录。

## 测试流程

1. 告知参与者：“请像第一次打开一款新游戏一样游玩。请尽量说出你正在注意
   什么和为什么这样操作；我不会解释下一步。”
2. 启动冻结候选的新档案并开始录屏或操作日志。
3. 主持人只记录时间，不提供界面指引。
4. 参与者完成或放弃第 1～2 章后，停止操作计时。
5. 不展示答案，依次询问：
   - “你做的哪一项环境操作改变了蚂蚁的什么行为？”
   - “你还记得第一只工蚁吗？你如何称呼或辨认它？”
   - “哪一段你主要在看蚂蚁，哪一段你主要在读界面？”
   - “有没有一段时间你不知道下一步该做什么？”
6. 保存逐字回答、关键时间码和主持人观察。不要只记录通过／失败。

主持人可以处理操作系统级故障，但不能指出观察手册、预测按钮、正确糖液位置、
正确推论或首工命名入口。若不得不解释，记录时间、原话并把对应指标视为未
无讲解完成。

## 逐人记录

每名参与者至少记录：

- 从“开始观察”到第一次有意义操作的秒数与动作；
- 第 1 章和第 2 章是否无讲解完成；
- 是否主动记住或命名首工；
- 对“环境干预如何改变行为”的逐字回答与编码；
- 任何连续 60 秒不知道下一步的区间；
- 主要看蚂蚁还是主要读任务文本，以及逐字理由；
- 关闭检查器时能否辨认首章关键护理行为；
- 卡住、误解、跳过、反复操作、帮助使用和主观感受；
- 完成、放弃或技术中断时间。

“有意义操作”指玩家根据当前问题主动完成预测、提交本章环境干预或打开观察
手册检查证据；单纯切换速度、暂停、随意点击或移动镜头不计。

## R21 Gate

只有前 5 名有效参与者同时满足以下全部条件，才能写 `PASS`：

- 至少 4/5 在 90 秒内完成第一次有意义操作；
- 至少 4/5 无讲解完成第 1～2 章；
- 至少 4/5 能解释一项环境干预如何改变蚂蚁行为；
- 至少 3/5 主动记住或命名首工；
- 没有人连续 60 秒不知道下一步；
- 玩家总体认为主要是在看蚂蚁，而不是主要在读任务文本；
- 首章关键行为在关闭检查器后仍能辨认。

有效样本少于 5 人只能写 `INCOMPLETE`。任一阈值未达到写 `FAIL`，并优先修复
第 1～2 章；不得因此进入 R22 或扩写第 3～6 章。自动测试、开发者窗口检查和
候选包存在都不能替代真人结果。
